# T21: bounded asset import and content workflow contract

This contract describes the implemented Godot 4.7.2/Windows local-project subset. It does not claim arbitrary project compatibility or production qualification. `tests/content-workflows-e2e.test.ts` uses isolated empty test projects, official MCP SDK calls and real editor/runtime processes. Test MCP form acceptance is a **MOCK**; it is not a human approval record.

- `import_project_png` accepts only strict base64 PNG bytes, at most 2 MiB and at most 4096×4096 pixels. The destination must be a project-local regular `.png` path with an existing parent. The caller supplies `expectedSha256:null` for create or the current exact lowercase SHA-256 for replace. No arbitrary host file path, external URL, importer settings or plugin-defined importer is accepted.
- Candidate bytes and all project inputs are copied to a disposable project. Godot's editor import and `ResourceLoader.load` must pass before the approved transaction writes the exact source bytes. Invalid PNG CRC, missing resources, hash conflict and unsafe paths fail without touching the original target. The transaction stages byte-accurate before/after images and a hash/size binary preview; validation failure rolls back. Godot-generated `.import` sidecars/cache remain engine-owned, not source assets to overwrite.
- An already enabled, independently authorized editor can receive `asset.scan` and `asset.status` after commit. The response distinguishes durable `persisted:true` from `editorSynchronization:OBSERVED` or `NOT_OBSERVED`; it polls native scanning/importing and confirms an imported `Texture2D`, without treating a post-commit timeout as rollback. Without such an editor, isolated import validation can pass but live synchronization is explicitly unobserved.
- Main development normalizes native scanning progress to 0..1 at the producer boundary: Godot 4.7.2 can report an overshoot after a rescan. Progress is only a display indicator; completion still requires real scanning/importing flags and resource readiness. The host's strict state schema is unchanged.
- Main's separate `manage_editor_resource` `png_texture` action is a source-byte snapshot, not this importer's cached resource reference. Its tighter limits are 16 KiB, 32×32, non-interlaced 8-bit RGB/RGBA and no metadata chunks. Hashes are bound through scene approval/commit, after which independent native pixels are embedded. This does not change the ingress limits above or grant live external texture support. See the [PNG snapshot contract](UI-AUTHORING-CONTRACT.md#png-来源快照main-开发源码).
- 2D slice: MCP creates a scene/script and imports a texture; native editor operations author bounded HUD controls, collision shape and local position animation, followed by exact approved save/reopen. A later hash-preconditioned `.tscn` transaction adds the imported sprite, navigation polygon/agent and a simple input script after closing the editor. A fresh Godot runtime verifies input state changes and a native 2D path. The scene move tool updates the main-scene reference after closing the editor.
- 3D slice: MCP creates a scene/script; native editor operations author a BoxMesh, StandardMaterial3D, box collision, ray, camera and bounded Node3D/Vector3 position animation. After native save/reopen, an exact approved `.tscn` transaction adds a NavigationMesh/Agent and the input script. A fresh runtime verifies interaction state, ray hit and synchronized 3D path.
- The editor's structured scene mutation remains deliberately limited to its declared unscripted graph and explicit instance policies. NavigationRegion/Agent, script attachment and arbitrary navigation mesh editing are **not** claimed as structured editor operations. Historical T21 slices use approved, isolated-engine-validated text candidates for these elements and Sprite2D. Main later adds a separate [single-frame native Sprite2D subset](SPRITE-2D-CONTRACT.md); this does not retroactively change T21's text-based acceptance or open arbitrary imported textures. 3D animation extends only local `Node3D:position` keys; a 2D/3D dimensional mismatch is rejected before mutation.
- Scene move's bundled-plugin exemption applies only to byte-identical shipped `.gd` files that do not contain the moved path/UID. Altered or extra plugin code, dynamic project references, unsupported imported assets and ambiguous references continue to fail closed. Asset rename/reference repair, non-PNG importers, custom import plugins, C#/other languages, skeletal/method/audio tracks, broad visual-shader node families and arbitrary gameplay scripts remain outside this bounded subset.

Acceptance must include full tests, a separate required Godot smoke run, frozen source identity and the G3 required-case assessment. Historical T16–T20 evidence is not a substitute for rerunning affected cases after source changes.
