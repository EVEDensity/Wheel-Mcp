# 测试暂存与关键证据保留

- 生产门禁的每一轮测试使用独立的 `wheel-gate-*` 系统临时根。测试子进程退出后，只删除该轮自己创建、路径和类型均已核对的临时根；清理失败会使门禁 FAIL，并在 `results.json` 留下精确路径与错误。不得扫描或清理用户的共享 Temp、Godot 项目或其他进程目录。
- `validateCandidateFiles` 在成功或失败后删除自己创建的 `wheel-validate-*` 隔离项目；原项目不受影响。验证摘要、失败代码和报告仍写入项目自己的 `.harness/validation/<id>/`。报告里的 stage 路径仅用于追溯，不保证验证结束后仍存在。
- 正式门禁保留 `manifest.json`、`results.json`、工具/请求清单及 `stdout.log`、`stderr.log`：它们是任务、失败排查和发布审计的关键原始证据，不能被“减少日志”误删。日常用户界面应优先展示状态、失败原因、测试计数及证据位置，不重复倾倒完整原始日志。
- 既有共享 Temp 旧目录不由新门禁追溯删除；历史或失败运行的证据也不自动删除。任何历史清理须先核对目录所有权、运行进程与保留要求，再按明确范围执行。
