# T19: bounded animation authoring contract

This is a deliberately narrow Godot 4.7.2 editor subset, behind the independently opted-in `scene.animation/v1` capability. It is not a general animation editor and does not imply production qualification. MCP write operations still require an exact scene preview and explicit form approval; a batch is one native Undo/Redo action, then a separate safe-save request validates and reopens the staged scene before replacing the source file.

- `create` accepts local `AnimationPlayer` and `AnimationTree` nodes. Native default `AnimationMixer.root_node = ".."` and `AnimationTree.advance_expression_base_node = "."` are the only accepted nonempty animation NodePath defaults. Moving a mixer requires an explicit retarget policy and is refused.
- `animation_clips` creates one owned `wheel` `AnimationLibrary` on an empty `AnimationPlayer`. At most 8 clips, 8 value tracks per clip, and 32 ordered keys per track are accepted. A clip ID and each track ID are stable ASCII identifiers; track IDs persist as animation metadata. T21 extends the first slice from canonical local `Node2D:position`/finite `Vector2` keys to local `Node3D:position`/finite `Vector3` keys; dimensional mismatches fail before mutation. Existing, external, imported, or shared animation resources are not edited in place.
- `animation_graph` creates an `AnimationNodeStateMachine` on an empty `AnimationTree`: 2–8 state IDs, a valid entry, 1–16 conditional transitions, a valid clip for each state, no ambiguous condition from one state, no automatic cycle, and no unreachable state. State IDs are Godot graph node keys, separate from their display labels. Transition IDs persist as metadata. The `Start` edge is automatic; authored edges use a named `parameters/conditions/<condition>` boolean.
- `animation_blend` creates one `AnimationNodeBlendTree` with exactly two `AnimationNodeAnimation` sources, one `AnimationNodeBlend2`, and the native `output`; all three port connections are verified. Its live amount is `parameters/<blendId>/blend_amount`.
- All graph resources and local libraries are copied/created for the proposed transaction, not mutated on the live scene during preflight. Native document snapshots include clip/graph signatures so a changed graph invalidates an approved plan. Save rejects stale track paths, missing clips, unsupported graph topology, shared nested resources, or pack/reopen drift. Failed writes do not register an Undo action.
- Runtime `get_specialized_state` observes the actual active state, playback position/length and conditions for a state machine, or the actual Blend2 amount. This is read-only. The real input-driven acceptance fixture supplies a **test-only** Godot script that maps D/A key events to graph conditions; the editor operation itself does not create gameplay scripts or claim arbitrary input binding.

Unsupported here: arbitrary track types/properties, skeletal/method/audio tracks, graph replacement, nested state machines, arbitrary BlendTree nodes, imported/linked/shared resource mutation, script creation, and live-client compatibility outside the tested fixture. Invalid or outside-matrix documents fail closed instead of receiving a partial-success response.

## Main development: bounded 2D transform channels

Editor bridge 0.3.8 additionally advertises `scene.animation_transform2d/v1` for write-enabled endpoints (28 capability maximum; read-only endpoints remain two). The host refuses rotation/scale requests against an older plugin before preview/approval. Existing position-only requests still require only `scene.animation/v1`. Upgrade host/plugin explicitly; no implicit installation. These changes are not in the immutable public v0.2.8 package.

`animation_clips` keeps the same limits and transaction model. A local, owned Node2D may use `property: "rotation"` with finite scalar keys in radians −32…32, or `property: "scale"` with strict `{x,y}` positive values in 0.0625…16 on each axis. They are native `Animation.TYPE_VALUE` tracks: continuous linear interpolation, loop-wrap enabled, transition 1, enabled tracks. No degree conversion, angle wrapping, mirror/zero scale, component subpaths, custom easing or 3D rotation/scale is implied. Duplicate target/property channels fail closed, even with distinct track IDs. Canonical local paths, dimensional checks, resource ownership, shared-resource refusal and staged save/reopen guards still apply. New-channel settings outside the contract are refused rather than silently omitted from a document signature.

Acceptance uses the official SDK stdio transport with explicit **MOCK**, not human, approval. Test-only editor Undo/Redo controls and native AnimationPlayer sampling are confined to isolated fixtures. After native save and editor reopen, the unmodified saved scene is also loaded through the real headless runtime bridge; public method calls `play`, `seek` and `advance` sample positions/rotation/scales. No expected transform is assigned by a test observer. This proves deterministic native sampling, not wall-clock animation performance or rendering. Existing position/state-machine/Blend2 tests remain required in their separate regression slice; adding this subset does not complete the broader animation roadmap.
