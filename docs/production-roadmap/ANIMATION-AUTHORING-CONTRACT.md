# T19: bounded animation authoring contract

This is a deliberately narrow Godot 4.7.2 editor subset, behind the independently opted-in `scene.animation/v1` capability. It is not a general animation editor and does not imply production qualification. MCP write operations still require an exact scene preview and explicit form approval; a batch is one native Undo/Redo action, then a separate safe-save request validates and reopens the staged scene before replacing the source file.

- `create` accepts local `AnimationPlayer` and `AnimationTree` nodes. Native default `AnimationMixer.root_node = ".."` and `AnimationTree.advance_expression_base_node = "."` are the only accepted nonempty animation NodePath defaults. Moving a mixer requires an explicit retarget policy and is refused.
- `animation_clips` creates one owned `wheel` `AnimationLibrary` on an empty `AnimationPlayer`. At most 8 clips, 8 value tracks per clip, and 32 ordered keys per track are accepted. A clip ID and each track ID are stable ASCII identifiers; track IDs persist as animation metadata. T21 extends the first slice from canonical local `Node2D:position`/finite `Vector2` keys to local `Node3D:position`/finite `Vector3` keys; dimensional mismatches fail before mutation. Existing, external, imported, or shared animation resources are not edited in place.
- `animation_graph` creates an `AnimationNodeStateMachine` on an empty `AnimationTree`: 2–8 state IDs, a valid entry, 1–16 conditional transitions, a valid clip for each state, no ambiguous condition from one state, no automatic cycle, and no unreachable state. State IDs are Godot graph node keys, separate from their display labels. Transition IDs persist as metadata. The `Start` edge is automatic; authored edges use a named `parameters/conditions/<condition>` boolean.
- `animation_blend` creates one `AnimationNodeBlendTree` with exactly two `AnimationNodeAnimation` sources, one `AnimationNodeBlend2`, and the native `output`; all three port connections are verified. Its live amount is `parameters/<blendId>/blend_amount`.
- All graph resources and local libraries are copied/created for the proposed transaction, not mutated on the live scene during preflight. Native document snapshots include clip/graph signatures so a changed graph invalidates an approved plan. Save rejects stale track paths, missing clips, unsupported graph topology, shared nested resources, or pack/reopen drift. Failed writes do not register an Undo action.
- Runtime `get_specialized_state` observes the actual active state, playback position/length and conditions for a state machine, or the actual Blend2 amount. This is read-only. The real input-driven acceptance fixture supplies a **test-only** Godot script that maps D/A key events to graph conditions; the editor operation itself does not create gameplay scripts or claim arbitrary input binding.

Unsupported here: arbitrary track types/properties, skeletal/method/audio tracks, graph replacement, nested state machines, arbitrary BlendTree nodes, imported/linked/shared resource mutation, script creation, and live-client compatibility outside the tested fixture. Invalid or outside-matrix documents fail closed instead of receiving a partial-success response.

## Main development: bounded 2D transform channels

Editor bridge 0.3.8 additionally advertises `scene.animation_transform2d/v1` for write-enabled endpoints (28 capability maximum; read-only endpoints remain two). The host refuses rotation/scale requests against an older plugin before preview/approval. Existing position-only requests still require only `scene.animation/v1`. Upgrade host/plugin explicitly; no implicit installation. These changes are not in the immutable public v0.2.8 package.

`animation_clips` keeps the same limits and transaction model. A local, owned Node2D may use `property: "rotation"` with finite scalar keys in radians −32…32, or `property: "scale"` with strict `{x,y}` positive values in 0.0625…16 on each axis. They are native `Animation.TYPE_VALUE` tracks: continuous linear interpolation, loop-wrap enabled, transition 1, enabled tracks. No degree conversion, angle wrapping, mirror/zero scale, component subpaths, custom easing or 3D rotation/scale is implied. Duplicate target/property channels fail closed, even with distinct track IDs. Canonical local paths, dimensional checks, resource ownership, shared-resource refusal and staged save/reopen guards still apply. New-channel settings outside the contract are refused rather than silently omitted from a document signature.

Acceptance uses the official SDK stdio transport with explicit **MOCK**, not human, approval. Test-only editor Undo/Redo controls and native AnimationPlayer sampling are confined to isolated fixtures. After native save and editor reopen, the unmodified saved scene is also loaded through the real headless runtime bridge; public method calls `play`, `seek` and `advance` sample positions/rotation/scales. No expected transform is assigned by a test observer. This proves deterministic native sampling, not wall-clock animation performance or rendering. Existing position/state-machine/Blend2 tests remain required in their separate regression slice; adding this subset does not complete the broader animation roadmap.

## Main development: non-destructive native source copies

Editor bridge **0.3.10** adds independent `scene.animation_copy/v1` (30 capabilities maximum, read-only remains two), together with `scene.animation/v1` and dependency binding. Upgrade host and plugin explicitly. This is a main-development feature, not a change to the immutable public v0.2.8 package.

`animation_copy` accepts exactly `path` (an empty local AnimationPlayer), `sourcePath` (a project-relative or `res://` standalone native Animation `.tres`), `sourceHash` (SHA-256 of exact source bytes), `clipId` (stable ID), and `targets` (1–8 explicit source-node → canonical local destination-node mappings). The operation creates one independent `wheel` library, never replaces a populated library or edits its origin. For example, map `Imported` → `Hero` to copy `Imported:position` into `Hero:position`. Sources must be UTF-8, unlinked files under 16 KiB; absolute/protected/traversing paths, links/junctions and hard-linked sources are refused by the host. This policy is not an OS sandbox against hostile concurrent local processes.

The native reader is an inert, bounded parser, not ResourceLoader, ConfigFile, `str_to_var` or an expression evaluator. It accepts one format-3 Animation resource with no dependencies/subresources/scripts, 1–8 contiguous enabled linear **value** tracks, transition 1, loop-wrap enabled and continuous update mode. Only `position` Vector2/Vector3, Node2D scalar `rotation` and positive Vector2 `scale` are copied with the existing target/type/range/time/key limits. Source imported flags may be true: the destination is newly owned, non-imported data. Only default animation step, boolean loop and declared inert metadata are supported. Duplicate/unknown fields, arbitrary constructors, method/audio/bone tracks and unused/missing mappings fail before approval or live mutation. Source dedicated `position_3d`/`rotation_3d`/`scale_3d` tracks, Skeleton retargeting, FBX/GLB/import caches, entire imported scenes, graph copying and arbitrary resources are **not** covered.

The exact preview includes the source fingerprint and all converted clip/track/key values and mappings, inside the unchanged 24 KiB approval budget. Host/native CAS rechecks source bytes before and after approval and before commit. One native Undo/Redo action and a separately approved safe save/reopen remain mandatory. After commit the source is detached: editing it does not modify, invalidate or rewrite the independent owned copy. Saving uses the owned library's signature and regular scene dependencies, not a permanent source-file link.

Tests export a real native `.tres` with Godot, reject malformed/executable sources, stale hashes/mappings and approval races, then check source immutability, Undo/Redo, save/reopen and actual headless AnimationPlayer samples at 0, 0.25, 0.5 and 1 seconds. Approvals are MOCK, not human UX, and no expected transform is assigned by an observer. The existing engine launch count and old direct-authoring/graph regressions are retained; this is not full imported-animation support.

## Main development: native 3D rotation and scale

Editor bridge 0.3.9 adds independent `scene.animation_transform3d/v1` on write-enabled endpoints (29 capability maximum; read-only remains two). Only `rotation_3d` / `scale_3d` require this extension, in addition to the base animation capability. They do not require the 2D extension; existing 2D tracks do not require the 3D extension. No capability fallback, implicit plugin installation or silent type conversion is allowed.

The same `animation_clips` transaction creates these two dedicated native track types on owned, canonical local Node3D targets:

- `rotation_3d`: strict `{x,y,z,w}` components, each finite in −1…1; squared length must differ from 1 by at most 0.000001 before native float32 conversion and after it. The MCP does not normalize or reinterpret Euler angles/degrees. Native `Animation.TYPE_ROTATION_3D` / `rotation_track_insert_key` stores the quaternion and uses native linear quaternion interpolation. This is orientation interpolation, not a multiple-turn rotation curve.
- `scale_3d`: strict `{x,y,z}` finite positive components, each 0.0625…16, checked before float32 conversion and on stored values. Native `Animation.TYPE_SCALE_3D` / `scale_track_insert_key` uses linear interpolation. Mirror/zero scale, shear, imported skeleton/bone subpaths and arbitrary 3D channels remain unsupported.

Dedicated track paths name only the target node, with no property/bone subname. Signatures carry an explicit `property` for these track types so rotation and scale on the same NodePath cannot alias. Existing `position` value tracks keep their `:position` path and original value grammar. Track settings must remain enabled, uncompressed, non-imported, linear, loop-wrap enabled and transition 1; unsupported live edits block even unrelated writes and native save. Clip/track/key limits, ownership, shared-resource refusal, exact approval, native Undo/Redo and pack/reopen checks remain unchanged.

Editor responses and request/plan/document hashes use full-precision JSON floats. Otherwise a legitimate nontrivial unit quaternion can fail exact-preview comparison, and distinct tiny numeric requests could collide in operation-ID hashing. Exact host request comparison is retained. The fixed acceptance also changes a quaternion component by 1e-15 under the same completed operation ID and requires CONFLICT, not replay or a second approval.

The existing 2D fixture now authors both dimensions in one scene, keeping the original 2D refusal/replay/undo/save checks and engine startup count. The saved scene is reopened in the editor and sampled through the real headless runtime at 0, 0.25, 0.5 and 1 seconds. Quaternion orientation, positive scale and legacy 3D position are read from the actual target; no test observer assigns an expected transform. Approval remains **MOCK**. These checks are deterministic native sampling, not GPU rendering, wall-clock performance, human approval UX or imported-animation support. Existing position/state-machine/shared-library/Blend2 regression cases remain separate and unchanged.
