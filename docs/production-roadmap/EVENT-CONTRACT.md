# Persistent runtime event contract (T04)

Only `runtime/event` notifications are written to `events.jsonl`. `runtime/ready` and other bridge-control notifications are not gameplay events. Every persisted line is one complete UTF-8 JSON object with `schema_version: "0.1"`, `source: "REAL"`, `run_id`, monotonically increasing `sequence` (starting at 1), UTC `timestamp`, `event`, and object `payload`. The stable event identity is `(run_id, sequence)`; clients can deduplicate at-least-once deliveries with that pair.

The bridge serializes event writes in arrival order. A tool response waits for queued event and process-log writes before returning; stop waits for the final drain. The in-memory notification ring holds at most 1,024 entries. The event reader keeps at most 2,048 parsed events and 100 malformed-line examples in memory while counting all malformed lines. It reads newly appended file bytes from the previous offset, keeps incomplete trailing lines pending, and reopens after file replacement/truncation. Older cursor pages stream from disk with bounded chunks. A malformed complete line is reported but cannot hide a later valid line.

`readRuntimeEventsSince` returns events strictly after the requested cursor. A cursor with another `run_id` is rejected, and `cursor_ahead` indicates a sequence beyond the known maximum. `cursor_expired` indicates that the requested history is no longer available or a sequence gap exists. Runtime event and stdout/stderr logs rotate into timestamped numbered segments at 8 MiB per segment; archived event segments remain readable by cursor. Each stream is limited to 64 archived segments plus the active file. Exceeding the quota fails the session explicitly instead of deleting earlier evidence or silently dropping new records. The raw evidence directory is local and remains subject to the broader path/permission work in T08–T09.

Persistent subscriptions store the cursor and pending delivery on disk. Polling before ACK may replay the same page; ACK must match its delivered page cursor exactly, so it cannot skip unseen events. Filtered-out events advance without an ACK because none was delivered. ACK timeout pauses delivery until acknowledged or resumed. `wait_for_event` defaults to future events after the current sequence; callers must specify a cursor or `includeHistory: true` to accept historical matches. Run changes are not silently merged.

Real engine and 10,000-event tests are in `tests/persistent-events-e2e.test.ts`; existing cursor/subscription tests remain in `tests/runtime-events*.test.ts`. D03 is tracked by `npm run baseline:defects`.
