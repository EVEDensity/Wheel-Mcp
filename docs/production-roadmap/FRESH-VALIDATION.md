# Fresh runtime validation contract (T06)

`reload_scene` reloads a scene in the same Godot process. It returns `scope: "scene_only"` and `code_freshness: "NOT_VERIFIED"`; it never claims that an edited GDScript or imported resource was reloaded. A caller that needs to validate code uses `dev_loop`, which starts a new Godot process for each attempt, even with no edits in that call.

Each attempt first hashes project source inputs, runs a fresh headless Godot editor import/parse preflight, and hashes those source inputs again. Generated `.gd.uid` and `.import` sidecars are excluded only from this preflight comparison because Godot may create them during import. Source changes during preflight fail with `CONFLICT`. After import, the complete project input set—including generated import metadata—is hashed before runtime starts, then hashed again after the bridge stops. A mismatch adds a failed `input_snapshot` check, returns top-level `code: "CONFLICT"`, and cannot be reported as PASS. `.git`, `.godot`, `.harness`, `node_modules`, and the configured evidence directory are excluded; unsupported symlinks and projects beyond the explicit file/byte limits fail closed. Full before/after file manifests remain in local attempt evidence.

The editor preflight registers `class_name` scripts and imports source assets before the new runtime loads a scene. Runtime checks and diagnostics are separate: a bridge-ready notification is not proof that project initialization succeeded. Autoload, global-class inheritance, imported SVG texture, dependent scene, and a deliberate `_ready()` error are exercised with real Godot in `tests/fresh-validation.test.ts`. A concurrent external script edit after the input hash is also a real-engine failure case.

The runtime handshake validates bridge protocol, project/run identity, and announced method capabilities. Methods absent from the actual handshake fail `UNSUPPORTED` before dispatch. The actual engine-reported version, not the executable filename, determines version status: Godot 4.7.2 is `VERIFIED` in the current evidence; other parseable Godot 4.3+ and unparseable builds are `NOT_VERIFIED`. Godot 3.x, Godot 4.0–4.2, and non-4.x major versions are rejected as `UNSUPPORTED`. A `NOT_VERIFIED` build may be used for exploration but does not inherit the 4.7.2 qualification.

D04 now tests the supported fresh-process contract: after `version = 1 → 2`, same-process scene reload remains explicitly unverified for code, while a new-process `dev_loop` reads `2`. D06 concerns legacy one-shot session continuity and remains assigned to T07; T06 does not claim to repair it.
